REE: A Scientific Research Entrance Exam for AI Agents

100 research problems in five scientific areas and 23 domains, posed as exams. The leading AI agents now outperform the expert solutions on about four of five of them, yet carry the average problem only about two fifths of the way to its upper bound.

Each problem gives an agent a statement, a working starter and development data, and up to twelve hours to work alone. Held-out test instances it never sees grade the result, beside the expert solution, the strongest publicly available human-designed solution to the same problem that can run within the task's budget, re-run within the same twelve hours with at least the agent's compute.

01

Why an entrance exam

Evidence that AI agents can do research is accumulating. Agents have improved the best known constructions for open mathematical problems and taken first place in a live heuristic-programming contest.

Each of these results is measured in its own units and against its own reference. A materials group or a neuroscience lab that is weighing whether to hand an agent one of its own problems needs a different number: how far does an agent go past the field's established methods, when it gets no more compute than those methods do?

REE measures exactly that. It poses research problems that a program can score on held-out instances and that have an established human solution able to run within the task's budget. Each becomes an exam: a statement, a working starter solution and development data define what the agent may use, and held-out test instances it never sees measure how far it gets. The expert solution, the strongest publicly available human-designed solution that can run within the task's budget, is re-run offline within the same twelve hours, with at least the agent's compute, and graded on the same instances. Every problem reads on one scale, from the starter solution (0) to the upper bound (100).

What REE measures

The margin over the expert solution

Not a leaderboard of recorded numbers. Each expert solution runs beside the agent: the same twelve hours, the same held-out test instances, at least the agent's compute.

E: the expert baseline, the expert solution's score. B: the agent's score.

02

How the exam works

Research communities across the sciences already pose and score problems with a measurable objective. REE poses each problem as an exam that an agent sits alone.

What the agent receives

  • a self-contained statement of the problem, its input and output and its metric
  • a working starter solution, which it may improve, replace or discard
  • development data, to fit, tune and check its own progress
Fixed compute allocation, no network access

One twelve-hour run

The agent writes, runs and revises code, measures itself on the development data and decides when to stop. Every version it saves is kept with its tokens, and the versions current at 1, 2, 4 and 8 hours are graded too.

Held-out grading

The final solution, the starter solution and the expert solution are scored by the same grader on held-out test instances the agent never sees, within the same grading time.

One scale for every problem

Fields score their problems in their own units: an error in degrees, a correlation, the cost of a set of delivery routes. REE fixes both ends of a scale at release, the starter solution at 0 and the upper bound at 100, and places every solution on it.

B = 100 · v − vstartvub − vstart

A score of 40 says the solution has covered 40% of the distance from the starter solution to the upper bound. On most problems the upper bound is the best value the metric can take by definition, such as zero error, so the end of the scale is fixed whether or not any method can reach it, and it stays fixed as agents improve. Where other benchmarks fix a reference solution at a set value, such as 1 in RE-Bench or 100 in MLRC-Bench, REE measures the human solution on the scale instead.

Illustrative example, not task data: a problem scored by an error, where lower is better
Score 40
The starter solution's error, 0.40, reads 0; the upper bound, zero error, reads 100.

The expert baseline

Each problem's expert solution is the strongest established human-designed solution to the problem that is publicly available and can be run within the budget of the task. It is judged by its reported performance on the problem. Where that does not separate the candidates, we prefer, in this order, an entry in the problem's organised evaluation, a method published for the problem, a reference method or a released tool, and a standard method of the field. It is not a one-to-one reproduction of its published original: it is configured as the agent's solution is, reading and writing the task's formats, fitted on the development data only and run offline within the task's time limits. It is re-run offline within the same twelve hours, with at least the agent's compute, and scored by the same grader on the same held-out test instances.

Its score is the expert baseline E. It can therefore differ from the best result reported for the problem in the literature. It is a reference point on the scale, not a pass mark: each agent is read by its margin over it, B − E. Both ends of the scale are fixed in advance and the baseline is measured on it, so later agents can be compared on the same scale.

Reading the data · Clinical medicine

Judging each recording against its own range

On seizure detection in EEG, an agent finds that models trained across patients fail on its validation data, drops them and judges each recording against its own range. Its development score rises from 0.14 to 0.53.

Reading the data · Statistical learning & forecasting

A hidden lattice behind structural breaks

On structural breaks in time series, an agent notices that some series take a small set of repeated values, reconstructs the multiplicative path behind them and infers the lattice of increments on either side of the break. It reaches 56.0, the highest score on the problem.

Strong methods are built from established ones

A language-model judge traced the central idea of the best final method of the two leading agents on each problem through papers, write-ups and public code. On 51% of problems it is the field's standard method, tailored closely to the problem's data and metric; on 45% it combines established methods, often from different strands of a field, into a pipeline built for the problem.

The judge rates nearly all combinations non-obvious. Counting those and the one method carried over from another field, the best method goes beyond tailoring on 44% of problems.

Combination · Molecular biology

Gene regulatory networks from single-cell snapshots

One run joins three strands of work: directional evidence from how the distribution of expression changes along the observation order, a prior over cyclic graphs, and an edge scorer trained on thousands of networks drawn from a simulator. Its development AUROC, a measure of how well it ranks true edges above false ones, rises from 0.88 to 0.95, and it reaches 71.7, the highest score on the problem.

Combination · Water

Chlorine in a drinking-water network

One run rebuilds the network's physics: it infers each scenario's hydraulics with the Hazen–Williams pipe-flow relation, moves chlorine through the pipes with a transport simulator of the kind water engineers use, and takes the median over an ensemble of pipe volumes. It reaches 67.3, ahead of every other run.

Transfer · Optimisation

A matched filter for black-box optimisation

The statement makes the test functions' family public. An agent finds the hidden shift of one component with a matched filter, the signal-processing tool for finding a pulse of known shape in noise. The step cuts its development error from 1.47 to 0.53, and the run leads the problem at 72.2.

Testing beyond the development data

Own test sets · Automated reasoning

When the development data stop separating versions

On confluence proofs for rewriting systems, both leading agents certify 8 of 9 development systems. One goes on to test on instances it writes or generates itself, about 800 by its own log, and on the held-out instances it certifies 62 of 100 systems. The other certifies 38 and exceeds the time limit on 4 more, which the task penalises. Both still score below the expert solution.

What held-out grading catches · Linguistics

A development score of 0.996 is not the answer

On identifying verbal multi-word expressions in text, one run selects its last refinements on the full development data and reaches an F1 of 0.996 there, on a scale from 0 to 1, then 0.288 on the held-out test instances. Another keeps a check on data it does not train on and reaches 0.512. The development data alone would rank the two runs the other way; held-out grading sets the order right.

The leading agents reach nearly nine tenths of their final score within four hours and keep adding in the hours after; GLM-5.3 gains more in the later hours. A run that ends early keeps its final version, which flattens Grok 4.7's curve.

Similar scores, different token use
Mean score against median output tokens per run

GPT-6.1 Sol's median run writes about five times the output tokens of Claude Opus 5.5's for a similar score, each counted by its own model's tokenizer. For each agent, how much a run writes says little about how well it scores: the rank correlation between the two is 0.20 to 0.31.
